## Interpretation for design brief — [confirmed, primary source]

- **Legally**, MIT permits copying/modifying/redistributing the code, including commercially, with no obligation beyond retaining the copyright notice in the software itself.
- **Explicitly, socially**, the author asks for a link-back credit if forked, and frames uncredited copying as "plagiarism." This is a norms request layered on top of a permissive license — legally optional, but the author has stated a clear preference.
- **Practical read for this project:** do not fork/reuse this specific repo's code or its distinctive layout (the exact "name / role tagline / About+headshot / Experience tab-list / 'Some Things I've Built' project-card grid / Writing list" arrangement is instantly recognizable in the dev community as "the Brittany Chiang template," and has already generated enough uncredited clones that she added the forking notice). Treat the *conventions* (single-page scroll, restrained accent-on-navy palette, fixed side social icons/email rail) as public-domain-level UX patterns safe to draw on, but build original layout, copy, and visual identity rather than the same section-for-section structure.
